Security

GlyphPDF is built for environments where documents must not leave the machine. Everything below is stated in the repository's own documentation and pinned by its test suite where noted.

The offline posture

  • No telemetry, no cloud. The app runs fully offline; there is no account, no subscription and no phone-home. Exports carry an explicit local-processing notice — "Processed 100% locally, no internet, no upload".
  • The one network-aware feature is consent-gated. The optional AI Chat panel talks to a local Ollama only, with a loopback guard that rejects lookalike hostnames; document content never leaves the machine. OCSP/CRL checks on the signing path ask for per-document consent and fail closed when refused.
  • Updates never happen silently. The updater fetches a small JSON manifest, requires consent at every stage, verifies the download's SHA-256 and its Authenticode signature before install, and refuses unsigned installers by design (it is dormant until a code-signed release ships).

Verify what you install

Every release is published with a .sha256 sidecar. Verify before installing:

Get-FileHash .\GlyphPDF-x64.msi -Algorithm SHA256

Compare with the value in the release's .sha256 file. Full instructions are on the Download page.

Document-security engineering

  • Redaction excises, it never paints over. Redacted text is removed from the content stream, so "covered" content is genuinely gone; a proof step refuses to certify what it cannot verify. The optional redaction audit log deliberately records only a region count and an after-hash — never coordinates or pre-image data that could fingerprint the original.
  • Sanitization removes 15+ hidden-data vectors (metadata, JavaScript, embedded files, and more), and the compression path's metadata strip runs the same full sanitize logic.
  • SHA-256 only. Digital signatures (PAdES B-LT/B-LTA) use SHA-256 hashing exclusively — no MD5, no SHA-1 — and RSA keys below 2048 bits are rejected before signing.
  • Form scripts are sandboxed. AcroForm Calculate/Format/Keystroke/Validate scripts run in a quickjs-ng sandbox with a CPU deadline.
  • Saves are transactional. Redaction and expiry writes run as single transactions with source-integrity (SHA-256) checks and atomic commits; a failed write leaves the source byte-identical.
  • Admin control. Machine policy lets administrators manage settings; managed values are always shown as "Managed by policy".

License posture on security-sensitive dependencies

The build enforces its dependency policy with hard errors: MuPDF (AGPL-3.0) and Poppler (GPL-2.0+) are never linked in-process; veraPDF (AGPL-3.0) runs as a subprocess only; DjVu exists as an optional importer, never an output format. Third-party licenses are inventoried in LICENSE-3RD-PARTY.md.

Audits and evidence

The repository carries its verification work in the open: a code-level parity scorecard, security audit records, and a per-item evidence ledger under docs/audit/ and docs/security/ on GitHub. Named open items are published rather than hidden — see the scorecard's still-open list.

Reporting a problem

A formal, dedicated disclosure policy has not been published yet. Until one is, please report security issues through the repository's GitHub Issues — for anything sensitive, say so in the issue and keep details minimal until the maintainer responds.
