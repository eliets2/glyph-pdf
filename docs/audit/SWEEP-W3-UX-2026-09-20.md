## Code-level pre-findings (from the source survey; verified by runs below)

These are observations from reading the flow surfaces before/at harness time;
each is confirmed, refuted, or annotated by the run evidence above.

- **Accessibility disclosure box** (`AccessibilityPanel.cpp:97`): "Detection
  only. … never certifies PDF/UA. Content tagging … is not yet available."
  The honesty box bounds the claim correctly IF the rest of the panel never
  overclaims (run F7 checks the fix loop and the zero-gaps wording "This is
  not a PDF/UA verdict").
- **Find & Replace contract** (`FindReplaceDialog.cpp:248`): count is shown
  BEFORE replace ("count shown before replace"), replace-all reports applied
  count + geometry/length-reflow warnings (moat M8). Count/Replace buttons are
  disabled when scope is unusable (packa-F1).
- **Redaction partial failure** (`RedactApplyDialog.cpp:410-460`): a failed
  sanitization gets a LABELED partial-result dialog (Retry Sanitize / Keep
  Redacted File / Discard Output), never a generic success banner; a FAILED
  proof gets its own critical ("Do NOT distribute this file…"). D01: after a
  successful retry the flow is never re-announced with the stale failure
  wording.
- **Save** (`HomeController.cpp:145-346`): external-change conflict gets a
  resolution dialog (Save As / Reload / Cancel) — "A silent overwrite is
  impossible"; save FAILURE is a modal, not a transient status (UX-14).
- **Cert-encrypt** (`CertEncryptController.cpp:50-160`): OK is gated on >= 1
  VALID recipient; ER-3 multi-recipient re-encryption warning discloses the
  session-key consequence BEFORE the dialog; engine failure = honest critical
  with "The original file was left unchanged."
- **Batch** (`BatchMode.h/.cpp`): skip-already-text is its own accounting
  bucket ("never counted as success OR failure"); W1-01: a preset's
  `onConflict: overwrite` NEVER bypasses the interactive overwrite confirm
  ("There is no silent overwrite"); capability-unavailable steps are DISPLAYED
  at selection and REFUSED at run with the registry's whyNot.
- **Signing** (`SigningRequestRunner.h`): mutation gate re-confirms SHA-256 at
  every step; coverage honesty — after signing, the step validates the signed
  bytes and records ONLY engine-attested facts; the progress panel is
  modeless "guidance, never a gate", with the advisory-order disclosure.
- **OCR single-page** (`OCRMode.cpp:765,820`): a zero-word recognition
  completes the run as an explicit retryable Idle ("OCR complete — no text
  recognized on this page") instead of stale stats. The skip-already-text
  DISCLOSURE exists in BATCH (own bucket) — the single-page screen has no
  already-text disclosure (F5 probes what a user actually sees).

## Friction inventory (ranked)

1. **[F2b-D1] FIRST-RUN PRESET SAVE FAILS — opaque error, no recovery.**
   `BatchPresetStore::save` (`src/core/BatchPreset.cpp`, save() at ~line 857) never
   creates its root dir (`AppData/<profile>/presets`). On a clean profile the first-ever
   "Save as Preset" fails with `…/presets/uxflowpreset.glyphpreset.json: cannot open for
   writing — The system cannot find the path specified.` The user cannot know this means
   "directory missing", and the Preset Pipeline — the newest Batch feature — is
   effectively unreachable on first use. **Fix (one line at the shared boundary):**
   `QDir().mkpath(m_rootDir)` (or `QDir(m_rootDir).mkpath("."))` at the top of
   `BatchPresetStore::save` — root-cause-once; covers save/rename/delete identically.
   Existing suites (TestBatchPresets) construct the store with a pre-existing test-rooted
   dir, which is why this never surfaced in CI.
2. **[F2a-F1] The merge completion modal asks "Would you like to open the output file?"
   but never NAMES the output** — the filename is only in a 5-second status-bar transient
   (`Successfully merged %1 files to %2`). A first-time user who misses the transient
   does not know where the merged file went. Fix: include the output path in the modal
   text (the modal already exists; add `.arg(outputFile)`).
3. **[F1-F1] Offscreen drag limitation (harness note, not a product finding):** the
   highlight drag did not place a mark under the offscreen platform; the suite staged
   the annotation through the production annotation model and the SAVE half of the flow
   is fully verified. Native confirmation still outstanding (same residual the R16 lane
   recorded).
