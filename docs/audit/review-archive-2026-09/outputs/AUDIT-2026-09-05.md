**F01 — Form creation can destroy the input file.** [FormManager.cpp:160](C:/Users/User/Projects/pdf/src/engines/FormManager.cpp:160) loads the source and saves directly to the requested output path. The real [AddFormFieldCommand.h:20](C:/Users/User/Projects/pdf/src/commands/AddFormFieldCommand.h:20) supplies the document path as both input and output, then ignores the returned failure. With a valid, text-bearing PDF generated by QPdfWriter, `addTextField(input, ..., input)` returned false with a PoDoFo `InvalidNumber` exception and reduced the original from **15,257 bytes to 0 bytes**. The same operation with a separate output path succeeded. This was reproduced both inside and outside the sandbox. Write to a sibling temporary file, finish and validate the write, then replace the original. Apply that protection at the shared save boundary across form mutations, and propagate failures to the UI. Add a regression using a real text/font-bearing PDF; the current tiny fixtures do not expose this failure.

**F02 — AI timeout creates a use-after-lifetime path.** [OllamaProvider.cpp:157](C:/Users/User/Projects/pdf/src/engines/ai/OllamaProvider.cpp:157) queues work with `[&]`, then connects a second callback that also captures worker-local result variables and a semaphore by reference. At [line 172](C:/Users/User/Projects/pdf/src/engines/ai/OllamaProvider.cpp:172), a 20-second timeout returns and destroys those variables without canceling either callback. A delayed response, or a delayed main event loop, can subsequently dereference dead storage. Give asynchronous state an explicit lifetime and abort/disconnect pending work on timeout. Test a local delayed response that arrives after the deadline. This is a demonstrated lifetime error in the code; an actual crash was not induced during the audit.

**F03 — The HTTP loopback check is a string-prefix test.** [OllamaProvider.cpp:51](C:/Users/User/Projects/pdf/src/engines/ai/OllamaProvider.cpp:51) accepts `host.startsWith("127.")`. The production validator returned true for `http://127.audit.invalid:11434`, a hostname rather than a loopback IP. No request or DNS lookup was made. If a similarly named remote domain is configured, the intended cleartext restriction is bypassed. Parse IP literals with the existing Qt network facilities and test actual loopback membership; handle `localhost` separately. Retain explicit allowlisting for intentionally remote endpoints.

**F04 — OCR review edits never reach the saved text layer.** The pane is explicitly labeled “RECOGNIZED · EDITABLE” at [OCRMode.cpp:346](C:/Users/User/Projects/pdf/src/modes/OCRMode.cpp:346). Its editor is populated, but there is no readback or text-change connection updating recognized words. Accept emits a signal without edited content at [line 449](C:/Users/User/Projects/pdf/src/modes/OCRMode.cpp:449). [EditController.cpp:894](C:/Users/User/Projects/pdf/src/shell/controllers/EditController.cpp:894) exports the cached original `m_lastOcrWords`. Correcting a recognition error therefore cannot affect the searchable copy. Make reviewed word state authoritative and pass it through Accept. Add a test that changes recognized text, saves, and extracts the corrected value. Also bind the cache to the reviewed page: the current dialog uses `viewer->currentPage()` while the payload uses `m_lastOcrPage`.

**F05 — Binarization reverses image polarity.** [OcrPreprocessor.cpp:65](C:/Users/User/Projects/pdf/src/engines/ocr/OcrPreprocessor.cpp:65) converts a 1-bit Leptonica pixel using `val ? 255 : 0`. In the actual binarizer output, that mapping reverses foreground/background. A white paper pixel changed from **255 to 0** in the probe. Binarization is enabled by default, so both recognition paths can receive an inverted page. Correct the 1-bit conversion and test both white paper and dark strokes. The existing preprocessing tests focus on orientation with binarization disabled, so they pass despite this defect.

**F06 — Comparison misses an entire added page.** [DiffEngine.cpp:44](C:/Users/User/Projects/pdf/src/engines/DiffEngine.cpp:44) compares only the minimum page count; the later move analysis does not create page-added/page-removed results. Comparing a one-page PDF with the same first page plus a unique appendix produced page counts **1/2**, one compared page, **zero added words, zero removed words, zero changed pixels, and zero page moves**. The change tree therefore has no entry for the appendix. Add explicit page insertion/deletion results and render them in the tree and reports. Use an end-to-end PDF comparison test; most of `TestDiffEngine` exercises Myers token operations rather than this document-level behavior.

**F07 — Office/CSV text extraction ignores font encoding.** At [ConversionManager.cpp:184](C:/Users/User/Projects/pdf/src/engines/ConversionManager.cpp:184) and [line 195](C:/Users/User/Projects/pdf/src/engines/ConversionManager.cpp:195), `Tj`/`TJ` string bytes are converted directly to QString without resolving the PDF font encoding/ToUnicode mapping. In the probe, the existing PDFium backend correctly extracted **“Shared first page”**, while Word/Excel output contained control/glyph codes such as `00 01`, `00 02`, etc. The same extraction function feeds CSV. This remains a defect even if native OOXML libraries are installed. Reuse the project’s PDFium text/coordinate extraction, and assert readable round-trip text from a subset-font fixture.

**F08 — Office extensions still misrepresent output format.** The fresh configure found neither `duckx` nor `OpenXLSX`. [ConversionManager.cpp:235](C:/Users/User/Projects/pdf/src/engines/ConversionManager.cpp:235) and [line 274](C:/Users/User/Projects/pdf/src/engines/ConversionManager.cpp:274) wrote HTML and CSV respectively, while reporting success for `.docx`/`.xlsx` output paths. The controller now warns after export, but a warning does not make the artifact valid OOXML, and batch conversion uses the same writer. Make the actual supported format determine the filter and extension, or disable native Office export until its dependencies are present. Test package structure and expected content, not just a successful return or a nonempty file. This July P0 remains open.

**F09 — Form Undo fabricates the prior state.** [EditFormFieldCommand.h:39](C:/Users/User/Projects/pdf/src/commands/EditFormFieldCommand.h:39) records only the old name; the old tooltip, required flag, and value remain default-initialized. [Undo at line 58](C:/Users/User/Projects/pdf/src/commands/EditFormFieldCommand.h:58) skips restoring the empty old value and writes an empty tooltip and `required=false`. Editing an existing required field and undoing can therefore remove its original metadata while leaving the new value. Snapshot the actual properties or restore a valid document/page snapshot. Verify edit → undo → reopen against an existing field. Handle failed writes before marking the command successful.

**F10 — Deskew is still functionally inert.** [OcrPreprocessor.cpp:247](C:/Users/User/Projects/pdf/src/engines/ocr/OcrPreprocessor.cpp:247) passes an 8-bit grayscale Pix to `pixFindSkew`. The probe emitted **“pixs not 1 bpp”**, returned angle **0**, and left a 3-degree tilted text image unchanged. Convert a working copy to the required binary format for skew estimation, then apply the detected transform to the intended image with a matching inverse transform. Test an actual small-angle skew with the normal preprocessing options.

**F11 — Failed OCR never resets the panel’s running state.** [OCRMode.cpp:427](C:/Users/User/Projects/pdf/src/modes/OCRMode.cpp:427) disables Run immediately. It is re-enabled when `setOcrResults()` delivers success, but missing documents/models/language data and worker errors return through [EditController.cpp:444](C:/Users/User/Projects/pdf/src/shell/controllers/EditController.cpp:444) without a completion signal to reset the panel. The user can be left with “Running…” and no retry. Send completion/failure to the panel on every exit. Test missing language data followed by a successful retry in the same panel instance.

**F12 — Compression still presents unsupported passes as active.** [CompressDialog.cpp:149](C:/Users/User/Projects/pdf/src/modes/CompressDialog.cpp:149) creates checked “Subset fonts” and “Remove unused objects” controls. The backend itself acknowledges these passes do not run at [PoDoFoBackend.cpp:3845](C:/Users/User/Projects/pdf/src/engines/podofo/PoDoFoBackend.cpp:3845). Zeroing their estimated savings fixed the estimate, but the controls still imply work is being performed. Disable/remove them with a clear availability explanation until their write paths exist.

**Code quality and validation**

The code inventory contains **269 C++ source/header files and approximately 50,453 lines** under `src`. There are useful existing boundaries between controllers, engines, document state, and backend libraries, plus meaningful signature/redaction guards and targeted regression tests. Those are worth keeping.

The main quality problem is incomplete contracts across those boundaries: a UI signal can report acceptance without transferring edits; a command can ignore an engine failure; an exporter can report success for the wrong format; an asynchronous callback can outlive its state. Fix these contracts before reorganizing files. The largest files—PoDoFoBackend at 4,161 lines, SignatureManager at 2,141, PdfEditorEngine at 1,644—are maintenance hotspots, but their size alone is not a reason for a broad rewrite. CMake’s repeated test/DLL setup and stale “fix shipped” comments also make evidence harder to maintain.

Validation performed:

- Fresh Ninja Debug configure/build against HEAD, using GCC 16.1, Qt 6.11 and the local vendored PoDoFo 1.1.0. PDFium, Tesseract, RapidOCR and qpdf were detected. Build completed all 530 steps with 11 compiler warnings, including vendor/test warnings.
- **84/84 CTest targets passed**, in 7.31 seconds on the final run. Initial Windows environment and sandbox settings-write failures were resolved for validation; they are not reported as product bugs.
- The two Djot tests initially assumed `<binary-dir>/../third_party/djot`. Their Lua fixture tree was copied into the isolated audit layout without modifying tests. Prefer a CMake-provided source/fixture path so arbitrary out-of-tree builds work normally.
- Runtime probes compiled the production OCR/endpoint code and linked the freshly built engine library. They checked actual image pixels, output bytes, PDF text extraction, document comparison results, and same-file versus separate-file form saves.
- Passing CTest targets can contain optional skipped cases. A full external veraPDF certification run, live AI service exercise, visual walkthrough of every mode, sanitizer campaign, release package audit, and fresh competitor benchmark were outside this audit. No statement here treats green CTest results as proof of complete parity.

**Recommended order of work**

1. Protect original documents during form writes and surface failed commands (F01); fix AI callback lifetime and endpoint parsing (F02/F03).
2. Make OCR review/save authoritative and repair preprocessing (F04/F05/F10/F11), with a corrected-text → saved-PDF extraction test.
3. Correct conversion text and format contracts, then page-count comparison (F07/F08/F06).
4. Repair form undo, remove unsupported compression controls, and reconcile the parity ledger (F09/F12).

Use the existing libraries and test framework. These findings call for bounded fixes and stronger workflow assertions, not a framework migration or a new abstraction layer.
