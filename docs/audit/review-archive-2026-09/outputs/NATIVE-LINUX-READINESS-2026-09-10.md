## Decision

Native Linux is a reasonable extension of this C++17/Qt 6 application. Keep the native UI and document engines. The immediate work is to make dependency discovery, installed resources, persistence, platform services, and release validation portable. It is **not currently a proven Linux application**. A rewrite is not justified by the porting issues found here.

The primary blockers are directly visible in source: Windows paths override package discovery globally; Release builds receive Windows linker flags on Linux; several targets copy Windows DLLs unconditionally; PDFium accepts exactly a Windows import-library checksum; non-Windows secret storage derives its encryption key from public identifiers; and Linux autosave replacement deletes the previous file before renaming the new one. These must be fixed before a Linux preview carries the same trust claims as Windows.

No production files were changed. No dependency was installed. Earlier environment probes reported `E_ACCESSDENIED` from `wsl --list --quiet` and an unavailable Docker daemon pipe. No usable native Linux environment was established. Consequently **no Linux configure, build, test, desktop session, or package installation was run**. The findings below are source evidence and explicitly proposed acceptance gates, not runtime certification.

## Native desktop integration and satisfaction

A native executable is only the first acceptance step. Qt's Linux distribution guidance requires the correct shared libraries, platform plugins and runtime search layout; test the installed app on a machine without the developer toolchain. Reuse Qt's CMake deployment support and CMake install rules instead of copying the Windows deploy script into a Linux shell script. [Qt Linux deployment](https://doc.qt.io/qt-6/linux-deployment.html)

1. **Desktop identity and opening files.** Add one stable desktop ID, matching icons and `.desktop` entry with the PDF MIME type and a correctly quoted file argument. [main.cpp:35–53](C:/Users/User/Documents/Codex/2026-09-05/read-c-users-user-projects-pdf/work/whole-project-2026-09-10/source/src/app/main.cpp:35) already handles application identity and positional files, but no desktop-file name or desktop metadata was found. Test Open With, multiple filenames, paths beginning with a dash, drag/drop, repeated launches, default-app registration and uninstall. The desktop entry standard describes the integration format. [Desktop Entry specification](https://specifications.freedesktop.org/desktop-entry/latest/)
2. **Wayland and X11.** Exercise both Qt platform backends on actual GNOME and KDE sessions. Check dialogs, popups, window restore, multi-monitor fractional scaling, pointer hitboxes, keyboard focus, clipboard/selection and tablet input where claimed. `QT_QPA_PLATFORM=offscreen` verifies neither compositor behavior nor native dialog behavior.
3. **Fonts and localization.** [main.cpp:97–103](C:/Users/User/Documents/Codex/2026-09-05/read-c-users-user-projects-pdf/work/whole-project-2026-09-10/source/src/app/main.cpp:97) loads bundled application fonts; QSS still uses fixed small pixel sizes and some `Consolas` fallback names ([theme_dark.qss:556](C:/Users/User/Documents/Codex/2026-09-05/read-c-users-user-projects-pdf/work/whole-project-2026-09-10/source/resources/theme_dark.qss:556), `:602`, `:635`). [AnnotationLayer.cpp:309](C:/Users/User/Documents/Codex/2026-09-05/read-c-users-user-projects-pdf/work/whole-project-2026-09-10/source/src/ui/AnnotationLayer.cpp:309) uses Arial for drawn marks. Confirm the actual bundled font resources resolve, use sensible native fallbacks, and separate UI font selection from PDF font embedding/substitution. Validate Arabic shaping/RTL, French/German label expansion, CJK document fallback, zoom and 125/150/200% scaling. Missing desktop fonts must not change saved form totals or measured document geometry.
4. **Accessibility.** Preserve native widget semantics and accessible names, but check custom canvas overlays and ribbon controls using a Linux screen reader, keyboard-only operation and high contrast. Qt exposes an accessibility framework; custom widgets need their own accessible interfaces where standard semantics are insufficient. [Qt Accessibility](https://doc.qt.io/qt-6/accessible.html)
5. **Filesystem expectations.** Run case-sensitive names, symlinks/hard links, read-only directories, removable media, full disks, interrupted network shares and concurrent external edits. Keep file identity separate from displayed path, and make atomic-replacement/metadata semantics explicit. On POSIX a successful rename can leave an existing file handle reading old content: viewer reload still matters even when Windows handle parking is unnecessary. The existing `.context/research/step3-persistence-topics.md` correctly identifies the need to refresh the viewer after writes; do not discard that protocol during the port.
6. **Desktop secrets and signatures.** Verify root-store configuration and enterprise CA provisioning inside the actual package. [SignatureManager.cpp:191](C:/Users/User/Documents/Codex/2026-09-05/read-c-users-user-projects-pdf/work/whole-project-2026-09-10/source/src/engines/SignatureManager.cpp:191) ignores the return value of `X509_STORE_set_default_paths`; surface trust-store initialization failures distinctly. Current PKCS#12 loading ([SignatureManager.cpp:275–300](C:/Users/User/Documents/Codex/2026-09-05/read-c-users-user-projects-pdf/work/whole-project-2026-09-10/source/src/engines/SignatureManager.cpp:275)) does not establish a Linux smart-card/PKCS#11 feature. Add a separate, evidence-backed hardware-token milestone only if targeted customers require it.
7. **Helpers and optional tools.** Office import, veraPDF, OCR languages, model files and future form-JS workers need install-location/runtime capability probes, not the builder's PATH. A missing helper should produce a useful remediation route without pretending a standard was validated. Do not accidentally download models or contact third parties when a fleet policy disables networking.

The dependency manifest should record exact versions, origin URLs, hashes, build flags, architecture and runtime assets for Qt's Core/Gui/Widgets/Pdf/PdfWidgets/PrintSupport/Svg/Network/Concurrent modules, translation tooling, PoDoFo, OpenSSL, libzip, OpenJPEG, PDFium, ONNX Runtime, OCR models/languages, Tesseract/Leptonica and qpdf. Package licensing should be reviewed against the actual redistributed dependency closure. Host installation of an unrelated library is not evidence of a GlyphPDF link dependency. Qt PDF has commercial and LGPLv3/GPLv2 licensing options and includes PDFium plus other third-party components; describing all PDF support as simply BSD would be incomplete. This report identifies the engineering review required and does not determine the project's legal obligations. [Qt PDF licensing](https://doc.qt.io/QT-6/qtpdf-licensing.html)

## Distribution sequence

**First:** build a relocatable staged native application, then an internal `.deb` for the first Ubuntu target using CMake/CPack or a small distro recipe. This gets a complete install/uninstall/update path under test with fewest new moving parts. Use a signed repository or an explicitly managed internal distribution route; do not market a checksum file alone as publisher authentication.

**Second:** evaluate Flatpak for wider desktop reach after the native package works. Its runtime can reduce dependency variability, but its sandbox changes document access, external LibreOffice/veraPDF execution, signing devices, local AI connections and credential access. Design those flows explicitly. Use portals for user-selected documents and printing, and avoid broad host filesystem/D-Bus permissions. Flatpak documents the runtime/sandbox model and portal use, as well as the Wayland/fallback-X11 permissions. [Flatpak basic concepts](https://docs.flatpak.org/en/latest/basic-concepts.html), [sandbox permissions](https://docs.flatpak.org/en/latest/sandbox-permissions.html)

**Later:** add RPM for actual enterprise demand, or AppImage for a proven portable-use requirement. Do not maintain four release channels immediately. A Flatpak/AppImage containing the Linux ELF app remains native; shipping a Windows executable under Wine does not satisfy this port.

The Windows release pipeline has useful safeguards: `packaging/build-msi.ps1` signs the application and MSI and verifies signatures, and release builds check required feature definitions. - An explicit support matrix and vulnerability response owner. Track updates for pinned native parsers/runtimes, not merely the top-level package version. Internal security claims need real hostile-file regression evidence and clear compatibility limits.
