```
rot   0: ux = x0 + vx        uy = y0 + H - vy
```

## Observation (new, design precision — NOT a W2B-1 regression)

`RedactionProof.cpp` `runIntersects` deliberately adds a 3×font-size ascender
headroom above each run's baseline ("over-attribution ... can only tighten the
proof, never loosen it"). That safety argument holds only for MISSED
redactions. My first-cut mark M0=(315,325,45×200) → user [87 287 682 727] sits
with its lower edge 682 inside the neighbor line's headroom (baseline 650 +
36 = 686): the proof over-attributed "KeepThisVisible public record", swept
for it, found it alive, and FAILED a geometrically correct redaction whose
excision had removed exactly the secret. Demonstrated in
`probe-w2c-loose.txt` (the 6-passed/1-failed first run). Rotation-independent
(user-space margin, any page shape) and precision-only (false ALARM, never a
false pass — the honest-failure direction is unaffected; the missed-spot leg
above still fails loudly). Recorded as a residual for the proof owner:
consider ~1.2×fs headroom or true glyph-box intersection.
