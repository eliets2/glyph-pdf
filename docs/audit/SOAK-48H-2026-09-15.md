## Soak methodology

A **detached Windows loop** — `D:\soak-48h.bat` (CRLF cmd batch, v2) launched
via PowerShell `Start-Process -WindowStyle Hidden` (loop PID **25228**, cmd.exe,
started 2026-09-15T01:44:41+03:00), so it survives this lane's exit; no visible
window is ever spawned (`QT_QPA_PLATFORM=offscreen` is exported to every
child; the app cycle additionally uses `-WindowStyle Hidden`).

**Loop bring-up note (recorded honestly):** the first launch (01:35:26+03) ran
3 passes with a broken script harness — the bat's reduced PATH hid
`System32\WindowsPowerShell\v1.0`, so timestamps/app-cycles silently no-op'd,
and an unescaped `)` inside the if/else echo blocks corrupted branch parsing.
That was a **soak-script bug, not a candidate defect**; its partial log
(passes 1–3: TestBatchMode flake recorded, 2/3 passes green) is preserved at
`D:\soak-48h-setup-attempt1.log`. The loop was stopped, the bat rewritten
(v2: absolute powershell path, goto-branching, ping sleep), end timestamp
reset, and the soak relaunched fresh at 01:44:41+03.

Per pass, forever until end timestamp:

1. `ctest --test-dir build-soak -j 1 --output-on-failure --timeout 900`
   (offscreen, serial; the 900 s ctest-side timeout is a hang safety net and
   does not override per-test TIMEOUT properties, e.g. TestWelcomeRoutes' 300).
2. Pass counter + ISO timestamps; exit code recorded. On ANY failed pass the
   failing test lines (`***Failed` / `***Timeout`) are extracted into the log
   and the loop **continues** — a soak records, it does not stop.
3. Between ctest passes: launch `build-soak\PdfWorkstation.exe` with
   `QT_QPA_PLATFORM=offscreen`, 60 s lifetime, then `taskkill /F`; the
   observed outcome is logged (`KILLED-AFTER-60S;taskkill-exitcode=1` =
   normal forced termination; `EXITED-EARLY;exitcode=N` = crash suspect,
   with the exit code).
4. 10 s pause (ping-based); log-size check each pass — at >50 MB the log
   rotates to `D:\soak-48h.log.1`.

Files: `D:\soak-48h.bat`, `D:\soak-48h-check-end.ps1` (STOP/GO against the
end timestamp), `D:\soak-48h-timestamp.ps1`, `D:\soak-48h-app-cycle.ps1`,
`D:\soak-48h.end` (end timestamp), log `D:\soak-48h.log` (+ `.log.1` after
rotation). Script sources are kept under `.context/soak/` (untracked).

## Honest scope — what this soak does and does NOT prove

**Proves:** repeated cold startup/shutdown of the real Release executable
survives for 48 h without hangs, crashes, or exit-code anomalies; the full
153-test serial suite passes deterministically-enough under hundreds of
repeated runs (flaky tests separate from genuinely broken ones); no
resource-exhaustion failure (handle/memory/file-lock creep) emerges over
hundreds of app lifecycles on this machine.

**Does NOT prove (recorded as not-covered):**

- **No real-user GUI marathon** — everything runs
  `QT_QPA_PLATFORM=offscreen`; no real display, no human interaction, no
  window-manager/DPI/multi-monitor variance, no modal-dialog-by-mouse flows.
- **No installer/uninstall cycles** — the MSI/packaging path
  (`packaging/`, `GLYPHPDF_RELEASE_BUILD=ON` legs) is not exercised at all.
- **No multi-day file-format fuzzing** — `fuzz/` corpora and long-duration
  malformed-input campaigns are out of scope; ctest fixtures are finite and
  mostly well-formed.
- **No graceful-shutdown exercise of the app cycle** — the 60 s app cycle
  ends in `taskkill /F` by design (hard kill), so save-prompt/close-event
  paths are only covered where unit/integration tests cover them.
- Single machine, single user profile, no network/printer variance, no
  concurrent instances; OCR model inference covered only to the depth the
  suite already covers it.
