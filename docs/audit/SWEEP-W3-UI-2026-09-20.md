## 1. Method (and its disclosed limits)

- **Offscreen Qt automation only** — `QT_QPA_PLATFORM=offscreen` +
  `QWidget::grab()` to PNG. No computer-use, no user desktop, no installed
  app was touched. One process per matrix cell renders the real
  `gp::MainWindow` through `Bootstrapper::createContext()` (the full
  production startup path, unlike the 09-09 probe which instantiated the
  window without the app bootstrap).
- **Matrix**: {1366×768, 1920×1080} × {QT_SCALE_FACTOR 1.0, 1.5, 2.0} =
  6 cells (R17 matrix). Per cell: welcome, all 8 ribbon tabs, 10 task
  screens + batch Preset Pipeline + comments pane, 7 dialogs, 3 themes
  (welcome + compare each), CJK/RTL fixture.
- **Machine audit** per cell (`audit-<tag>.json`): every ribbon entry's
  text/icon-asset/tooltip/enabled state vs the ToolRegistry action state;
  disabled-reason disclosures; welcome card inventory; status-bar labels;
  per-grab ACTUAL pixel size; clip/truncation suspects; dialog widget
  inventories + focus chains; theme palette contrast ratios; CJK engine
  render ink fraction.
- **Resources**: the probe compiles the app's own AUTORCC-generated
  `qrc_resources.cpp` (+ translations qrc) — icons and theme QSS render
  exactly as shipped, eliminating the 09-09 probe's circle-fallback
  harness artifact.
- **Fonts (harness adaptation, disclosed)**: offscreen has no desktop
  fallback; Segoe UI/Consolas loaded explicitly, Manrope→Segoe UI,
  JetBrains Mono→Consolas substituted (matches main.cpp's tolerate-absent
  bundled-font path).
- **Dialogs** are opened with `show()` (non-modal) so automation can grab
  and close them deterministically; the production `exec()` entry points
  are exercised by the R15–R17 test waves (in-suite, passing at this tip).
- **Viewer canvas does not paint offscreen** (confirmed at this tip; same
  limit the 09-09 review disclosed). Document-rendering claims therefore
  use the production renderer directly: `PdfiumBackend::renderPage` (the
  same pdfium raster the viewer paints), captured as
  `cjk-engine-render.png`.
- Fixtures are synthetic (`QPdfWriter`), no private content. Runner:
  `tools/uisweep/run_matrix.sh`; probe source: `tools/uisweep/ui_sweep_probe.cpp`
  (probe exe SHA-256 prefix `d15108980dfd3f00`; links the same
  pdfws_ui/engines/commands/core libs as the shipped app).

Evidence root (disk-only, gitignored): `.context/ui-sweep/<tag>/` with
`audit-<tag>.json`, `rc-<tag>.txt` ("DONE" × 6/6), all PNGs, `matrix.log`.
All 6 cells finished with per-cell rc=0 and rc file "DONE".

## 3. Findings (ranked)

### P1 — broken at the acceptance viewport

- **F1 · Task-screen minimum width exceeds 1366×768 (all 10 task
  screens).** Measured from actual grab sizes (the offscreen window grows
  without bound; a real window manager would clamp and clip the
  right-hand panels instead): compare 1687×768, batch 1687×798,
  ocr/redact/signature 1919×798, measure/accessibility/form/pdfa/pages
  1973×798. The over-minimum scales exactly with QT_SCALE_FACTOR
  (×1.5 → 2531–2960; ×2.0 → 3374–3946), so this is logical-px minimum
  size, not a rasterization artifact. At 1920×1080/100% compare, batch,
  ocr, redact, signature fit; measure/accessibility/form/pdfa/pages still
  overflow by 53 px. Only the welcome honors 1366×768. Consequence on a
  real 1366-wide display: the SIGN DOCUMENT panel (and equivalents) is
  unreachable. Driver is the minimumSizeHint sum of viewer + right panel
  + ribbon. Production layout — recorded for a fix lane (not this lane's
  code). Evidence: `grewPastRequested: true` + `grabSize` per screen in
  every audit JSON.

### P2 — degraded

- **F2 · Theme switch is partial.** After `toggleTheme` to Light (and
  HighContrast), QSS-styled chrome (menu bar, ribbon, tables, status bar,
  screens strip) switches, but construction-time inline-styled surfaces
  stay dark: the welcome card grid + Batch/Compare links
  (`WelcomeWidget.cpp` builds stylesheets from `gp::Theme::*()` at
  construct time), the compare preview canvas, the Properties panel, and
  the mode-strip theme chip which still reads "DARK" under Light (a
  stale-disclosure bug). Contrast ratios themselves pass everywhere
  (12.6–21.0:1). Evidence: `theme-light-welcome.png`,
  `theme-light-compare.png`, `theme-highcontrast-*.png` in each cell.
- **F3 · Print summary surface absent at this tip.** The Comments pane
  renders (thread list, filters, reply editor, Post/Reply) but has NO
  "Summary PDF…" button — the printable-summaries work lives on
  `feat/printable-summaries` (b06b2f0, 8184a95, 2eb4ff6; suite green
  there per its lane handoff) and is **not merged** into
  feat/parity-glm. Matrix cell 3b fails at b17106a; re-verify after
  merge.
- **F4 · 13 ribbon entries have no icon asset** (UI05 residual).
  View: zoomIn, zoomOut, actual, fitWidth, fitPage; Edit: editText;
  Organize: insertPage, deletePage; Comment: line, arrow, poly, pencil;
  Forms: import. `editText`, `zoomIn`, `zoomOut` are CONFIRMED rendering
  as the generic circle fallback in screenshots; `actual`/`fitWidth`/
  `fitPage` appear to render real glyphs despite the missing asset name
  (an alternate icon path or renamed resources — needs the owner's
  one-line disposition either way).
- **F5 · Compress preset tiles overlap.** In the Optimize dialog the
  four preset cards (SCREEN / EBOOK / PRINTER / CUSTOM) collide —
  borders intersect and the CUSTOM tile partially covers PRINTER.
  Readability survives; geometry is wrong. `screen-compress-dialog.png`.

### P3 — polish

- **F6 · Tooltips missing on 110 ENABLED ribbon buttons** (Home 11,
  View 17, Edit 10, Organize 12, Comment 15, Convert 15, Forms 15,
  Protect 15). The 36 disabled entries all disclose their reason on the
  accessible channels — the gap is only the enabled set.
- **F7 · Truncations**: comments filter row buttons clip to stubs
  ("C", "lear Filter", "E…", "Su…Fil…") in the 245 px pane; OCR
  correction placeholder "Correct the selected w…"; compress slider
  labels truncate to unreadable stubs; Preferences "Current version:"
  row sits tight against the dialog edge; the signature appearance
  preview draws overlapping placeholder lines (verify natively —
  possible font-substitution artifact of the harness).
- **F8 · Welcome fold**: at 1366×768 the Batch/Compare links + Recent
  files are below the fold (a sliver of the links row peeks at the
  edge); the welcome shows no visible drop-target affordance (drag/drop
  is handled at MainWindow level; `WelcomeWidget.acceptDrops == false`);
  the "All Tools" route is not on the welcome — it lives in the
  workspace Tools chooser (design disposition per R15/R16, recorded for
  the product owner).
- **F9 · zh-CN fixture unproducible on this host**: no installed family
  covers simplified Chinese (only `SimSun-ExtB`, a rare-ideograph
  supplement). The fixture therefore embeds ko (Malgun Gothic), ja
  (Malgun Gothic fallback), ar (Segoe UI) and RECORDS the zh skip in
  `cjkLineFonts`. The engine render shows real glyphs for every embedded
  script — no tofu. zh rendering remains covered by the R17 in-suite pin
  (TestUiAccessibility passes at this tip) but is UNVERIFIED pixel-level
  on this machine.
- **F10 · Status bar pre-document**: the welcome shows "PAGE 1 /
  ZOOM 100%" chips before any document is open (minor disclosure
  oddity).
